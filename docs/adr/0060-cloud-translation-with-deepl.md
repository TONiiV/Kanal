# ADR 0060：云端翻译先接 DeepL，其他服务商以后接同一个 `IMtProvider`

状态：accepted，2026-10-14。

*本地转写 · 云端翻译* 模式一直不可用，因为不存在独立的云端翻译提供者。Gladia 只在转写会话内部翻译，
没有纯文本翻译接口。我们决定：新增 `DeepLMtProvider`，实现现有的 `IMtProvider`。其他服务商以后实现
同一个接口，不在接口上再加抽象层。

## 决定

- **DeepL 先上。** 它支持 zh、de、pl、en，有免费套餐，并且 `context` 参数可以带上最近的定稿句子
  来稳定术语。`context` 不计费。
- **编排器不变。** 唯一的判断仍是 `if (!asr.Caps.Translation)`。选哪家服务商只发生在
  `PipelinePlanner`，和选本地还是云端同一个位置。
- **只有文本离开本机。** 提供者只收到定稿句子的文字和最近几句定稿的文字，不接触音频。
  *本地转写 · 云端翻译* 因此仍显示「只有文字离开本机」。
- **密钥存放。** 密钥以 `ApiKeyEntry`（provider 为 `deepl`）保存在 `settings.json`，和 Gladia 密钥一样，
  是明文 JSON。开发时可用环境变量 `DEEPL_API_KEY`，已保存的密钥优先。设置里只有一个输入框，显示为掩码。
- **主窗口不出现服务商名称。** 模式行只说「没有云端翻译密钥」。服务商名称只出现在设置里。
- **免费还是付费服务器由密钥决定。** 以 `:fx` 结尾的密钥用 `api-free.deepl.com`，其他用 `api.deepl.com`。
- **错误带代码。** 456（额度用完）和 403（密钥无效）抛出 `MtProviderException`，代码经
  `AsrEvent.Error.Code` 传到主机，主机用操作员的语言显示。其他错误保持英文原文。
- **DeepL 不支持的目标语言被跳过。** 不抛错，其余语言照常翻译。

## 暂不做

- 正式/非正式语气（`formality`）：使用 DeepL 默认值。
- 术语表（glossary）。
- 用量与费用显示。
- 第二家服务商。需要时新增一个 `IMtProvider` 实现和一个规划器分支。
- 把密钥放进系统钥匙串。Gladia 密钥也没有，改动应一起做。

## 考虑过的方案

- **用 Gladia 做纯文本翻译：** 没有这种接口。
- **在 `IMtProvider` 上再加服务商抽象层：** 接口已经让服务商可替换，再加一层只增加代码。
- **用云端大模型 API 复用 `MtPrompt`：** 术语一致性靠提示词，结果不稳定，延迟更高。以后可以作为另一个实现加入。
