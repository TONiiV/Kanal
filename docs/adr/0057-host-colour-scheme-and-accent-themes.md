# 主机支持配色方案与强调色主题，颜色全部来自应用自有画刷

状态：accepted，2026-10-11。

主机原先锁定浅色（`RequestedThemeVariant="Light"`），原因是继承 FluentTheme 深色变体后控件前景色不可见。
现在主机要提供 Light / Dark / System 三种**配色方案**和若干**强调色主题**。我们决定：主机的每个颜色都来自
应用自己定义的画刷，浅色、深色各一套，永远不继承 FluentTheme 的默认颜色。

## 决定

- **范围**：只影响桌面主机。移动字幕页继续跟随手机系统设置。外观是设备偏好，不进入 `room.snapshot`。
- **默认 Light**：升级后界面不变。选择按机器全局保存在 `settings.json`，点击即生效，无需重启。
- **System 实时跟随**：会议进行中操作系统切换深浅色，主机立即跟随。
- **深色调色板复用移动端深色 token**，两端深色观感一致。
- **强调色主题只改品牌色**：`Brand*`、`SystemAccent*`。纸面、墨色、分隔线不变，转写正文可读性不受装饰色影响。
- **语义色锁定**：录音、暂停、告警和说话人颜色不随强调色主题变化，只随配色方案取深色版本。
- **说话人颜色**：仍用 `RoomState.Palette` 的同一组 hex，两端共用。调色板用于图形（分隔线、色条、圆点），在浅、深两套 sheet 和 paper 上都达到 3:1。
  会议记录不保存说话人颜色，重新打开时从调色板推导，所以旧会议也换成新颜色。说话人颜色只用来区分同一场会议里的人，这个变化可以接受。
  说话人姓名是文字，用由说话人颜色推导的文字色调：浅色纸面向墨色混合，深色纸面向白色混合，保证 4.5:1。同一颜色不可能在两种纸面上都达到 4.5:1。
- **对比度由单元测试强制**：每个主题的每个变体，正文 ≥ 4.5:1。
- **五套预置主题，避开红、橙、黄**：Kanal 靛蓝（默认）、松绿、海蓝、鸢尾紫、石墨。红、橙、黄会和录音、
  暂停状态混淆。`BrandAccent` 点缀色固定不变。不提供自定义或导入主题。
- **`SystemAccentColor*` 放在根资源字典**：放进 ThemeDictionaries 后 FluentTheme 会忽略它们，改画默认蓝
  `#0078D7`。所以切换主题或变体时，代码直接改写根字典里的这组值。只有像素对比能发现这个问题。
- **应用图标与强调色无关**：保留现有标志形状，改为银灰质感，浅、深两版。窗口图标和 splash 随配色方案切换；
  exe、安装包和 dmg 的图标在编译时固定，用浅色版。

## 考虑过的方案

- **继续锁定浅色**：最省事，但无法满足深色环境下的操作员。
- **继承 FluentTheme 深色变体**：已经证明会让控件前景色不可见。
- **强调色主题改整套调色板**（纸面带色调）：转写正文的对比度会随装饰色漂移，被拒绝。
