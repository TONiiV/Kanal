# 再次录制续写同一场会议：一条记录，多个 run

状态：accepted，2026-09-23；2026-10-13 修订（run 编号、编号 0056 → 0059）。

推翻 [ADR 0054](0054-meeting-record-lifecycle-and-storage.md) 的决定 1、决定 3，以及「明确排除」
里的「一条记录装多次会话」。0054 的其余决定不变。

## 背景

操作员反馈：会中停下录制（茶歇、换议题），再按录制，得到的是一条新记录。一场会议于是散成几条，
每条只有一段转写和一段录音，标题各自生成，导出也只各带一段。操作员要的是：同一场会议里停了再录，
**接着写进同一条记录**。

0054 当初排除这件事的理由是真实的：每次 Start 必换 `RoomId`，ASR 的 utterance id 归零，把两次
会话写进同一个 `transcript.jsonl` 会按 id 互相覆盖。本文保留这个前提，只换解法：不共用文件。

## 决定

1. **run。** 一次 Start…Stop 是一个 run。一条记录由若干 run 组成。run 1 写 `transcript.jsonl`
   与 `audio.wav`；编号为 n 的 run 写 `transcript-{n}.jsonl` 与 `audio-{n}.wav`。每个转写文件
   保持自己的 id 空间，文件里的 id 不改写。读取整条记录时按 run 的顺序拼接；第 2 个及以后的 run，
   id 在内存里加上 run 的位置作前缀（`2/u1`），不会撞。第 1 个 run 的 id 不变，只有一个 run 的
   记录读出来与以前相同；续写时实时 run 的 id 也从 `u1` 开始，所以之前的 run 全部加前缀，
   第 1 个 run 也加（`1/u1`）；发言人标签同样加前缀（`1/S1`），不进入实时发言人模型。
2. **run 编号只有一处来源。** `MeetingRecord.NextRun(folder)` 从「run 数 + 1」开始，跳过两类
   编号：记录里已有 run 用到的文件名，以及磁盘上已存在的文件。比较不区分大小写。原因：转写日志
   打开文件时会截断它，而导入的记录可以把任意纯文件名登记为 run 1，例如 `transcript-2.jsonl`。
3. **`meeting.json` 是 run 的清单。** 新增有序的 `runs`：`{ transcript, audio, startedAt,
   endedAt }`，`audio` 在未录音时为 null。记录的 `StartedAt` = 第一个 run 开始，`EndedAt` =
   最后一个 run 结束。`meeting.json` 与 `.kl` 包的 manifest 升到 schema 2；读取接受 1 与 2，
   写出一律 2。schema 1 的记录按一个 run 读（旧字段 `transcriptFileName` / `audioFileName` 只读
   不写）。工作空间与注册表文件仍是 schema 1。旧版本会拒绝打开 schema 2 的记录：这正是 0054
   「拒绝而不是读一半」的规则。
4. **信任边界。** `runs` 里的每个文件名都按「纯文件名」校验：拒绝 `..`、分隔符、绝对路径、
   `C:x` 这类盘符相对路径，以及以点或空格结尾的名字（Windows 会把它们解析成另一个文件）。两个
   run 指向同一个文件（不区分大小写）也算损坏。不合格的条目让整条记录报为损坏，绝不跟随。
   `.kl` 包的 manifest 同样校验，且只解出清单里点名的文件。
5. **绑定规则（取代 0054 决定 3）。** 选中从未录过的记录（`StartedAt` 为空）→ 用它，作为
   run 1；选中已录过的记录（`StartedAt` 不为空）→ 续写为下一个 run。崩溃后 `EndedAt` 为空的
   记录也算已录过。什么都没选 → 新建。「新建会议」按钮仍是另起一场的方式。知情确认弹窗在续写时
   写明续的是哪一场（`consent.continue`）。取消确认：磁盘上什么都不变。启动失败：`meeting.json`
   恢复原样，不留新 run，也不留它的文件（文件在会话启动成功后才创建）。
6. **屏幕。** 续写时，先载入之前各 run 的句子，再接实时句子；标题保持记录上的标题，不自动
   重命名。run 与 run 之间不加分隔线（需要给气泡加属性并改模板，本次不做）。
7. **所有读取方按顺序读全部 run：** 浏览、Markdown 导出、刻度尺、文件页签、`.kl` 导出与导入
   （全部转写；录音仅在勾选时；清单在 manifest 里）、损坏记录的恢复、删除（删整个文件夹，天然
   覆盖）。

## 明确排除

- **手机端只收到当前 run。** 中继频道仍随每次 Start 更换；迟到的参与者看不到之前的 run。
- **发言人标签按 run 重新开始。** run 2 的 S1 与 run 1 的 S1 不保证是同一人；之前各 run 按原始
  标签显示，改名与合并只作用于当前 run。
- **Markdown 导出的知情确认只写最近一个 run 的确认时间。**
- **记录的语言只跟随最近一个 run。** 浏览视图按 `record.Languages` 建列，只在更早的 run 里出现
  过的语言不单独成列。
