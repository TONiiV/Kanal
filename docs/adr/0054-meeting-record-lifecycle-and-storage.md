# 会议记录的生命周期与存储契约

状态：accepted，2026-09-08。

延续 [ADR 0051](0051-peer-meeting-workspaces.md)（平级工作空间拥有会议记录）。0051 冻结了记录的
归属边界，并明说「文件格式、迁移、跨空间移动、共享和运行中切换行为仍需独立设计」——本文补的
就是那份设计。同时补上 [`docs/specs/meeting-workspace.md`](../specs/meeting-workspace.md) 未确认
清单里的「工作空间内活动会议与浏览记录关系」，以及
[`docs/design/meeting-workspace.md`](../design/meeting-workspace.md) 验收项「工作空间切换不混淆
活动会议与所浏览记录」所依赖的契约。

## 背景

工作空间、会议记录、转写、录音四者今天是断开的：

- 一场真实会议**不写进任何会议记录**。`MeetingRecord.TranscriptPath` 只在导入外部文件时被设置，
  导出时被读取。转写靠操作员手动导出，落在全局转写文件夹并以 `RoomId` 命名；录音落在全局音频
  文件夹的 `{RoomId}.wav`。两者都与工作空间无关。开一百场会，工作空间里依然一条记录都没有。
- 点击左栏的会议记录「只设置 `SelectedMeeting`，别的什么都不做」。中栏正文不动，只有标题行会
  跟着变，于是标题和正文对不上。更糟的是，选中项变化会 `Titling.Reset()`，而实时会话的下一句
  定稿又会触发一次命名，生成的标题被写到**正在浏览的那条旧记录**上。
- `MeetingRecord` 早就有 `StartedAt` / `EndedAt`，全仓库没有一行代码写过它们。schema 是按
  「一条记录 = 一次开始、一次结束」设计的，只是从未接线。

## 决定

### A. 生命周期

1. **一条记录 = 一次会议。**「续录」即既有的暂停／继续语义，不引入「一条记录装多次会话」的容器。
   每次 Start 生成新 `RoomId` 是刻意的——ASR 的 utterance id 会归零，复用频道会让新会议按 id 覆盖
   旧会议的记录——把两段会话塞进一条记录会把这个冲突带进文件系统。`StartedAt` / `EndedAt` 首次
   接线。
2. **记录在知情确认之后才创建。** 点录制先弹知情确认，「确认并开始」的瞬间才创建记录、写入
   `StartedAt`、拼出标题。取消等于什么都没发生，不留空白记录。
3. **绑定规则**：当前选中的是空白（从未录过）记录 → 用它；是已结束的记录、或什么都没选 →
   新建一条并选中。
4. **没有工作空间就不能开始会议。** 首次启动自动创建 `Documents/Kanal`，工作空间名 `Kanal`。

### B. 存储

5. **工作空间是转写的唯一存放地**，边开边写。录音已经是边开边写的（`WavWriter` 每约 2 秒补一次
   RIFF 长度，「一小时留在内存里意味着一次崩溃赔掉全部」），转写没有理由采用更差的策略：否则
   主机中途崩溃会留下能播的录音和一个字都没有的转写。
6. `meetings/<id>/` 下放 `transcript.jsonl`（追加写）、`audio.wav`、`attachments/`。**记录 id 只用于
   链接，不作显示名。**
7. **`RoomId` 退出文件系统**，退回去只当中继频道 id。它按定义是 bearer capability（128 位随机，
   要进公开的 Realtime topic），把一个能力凭证写成文件名本身就不对；何况它每次 Start 都变。
8. 设置里的 `AudioFolder` 输入框**删除**。旧设置指向的既有录音留在原地，不做迁移——反查需要靠
   `{RoomId}.wav`，而第 7 条正要让 `RoomId` 离开文件系统。

### C. 标题

9. 默认标题 = 工作空间名 + `StartedAt`（到分钟），例：`Kanal 2026-09-08 14:30`。记录创建到开始
   录制之间显示「新会议」。用 `StartedAt` 而非 `CreatedAt`：日期时间指会议什么时候开的，不是
   文件夹什么时候建的。
10. **模型生成的标题覆盖默认值。** 默认值必须走占位符路径写入，不得经 `Titling.Rename()`——那会
    置 `NamedByHand = true`，从此永久关闭自动命名。
11. **手工重命名校验工作空间内唯一**，撞名拒绝并提示；**模型生成撞名时自动加后缀**。校验只作用
    于这两条路径：默认标题带精确到分钟的时间戳，天然近似唯一。

### D. 活动会议与所浏览记录

12. 录制过程中点击另一条记录，**中栏切换**到那条记录的内容，只读。
13. **所有写操作跟随活动会议**——标题生成、发言人改名、未来的旁听 Agent；中栏只是查看器。
14. 返回路径：左栏的活动会议常驻高亮，中栏顶部一条「正在录制《x》· 返回」的横幅，仅在中栏显示的
    不是活动会议时出现。

### E. 中栏

15. **中栏保持无页签。**
16. 正文旁增加**导航刻度尺**：结构层实时铺底（按发言人切换），语义层在会议结束后叠加。
17. 语义层**复用「要点与决策」的议题边界**，不新增模型调用。一份数据两处渲染，刻度与议题永远
    不会自相矛盾。

### F. 右栏

18. 页签为 要点与决策 / 发言人 / 文件 / （未来）Agent，**可横向滑动**。
19. 文件树只做**显示与从文件系统导入**。让模型读取附件是一个有安全后果的独立决定，不在本文范围。

### G. 导入导出

20. **JSON 导出取消**，Markdown 导出保留在会议的三点菜单里。结构化数据改由记录文件夹承载，不是
    能力缩水。
21. `transcript.jsonl` **存储保留**，导入继续接受 json。刻度尺的语义层与句子回放都需要「这句话在
    音频的第几秒、谁说的」这样的锚点，Markdown 存不下。
22. **单场会议的迁移包**，可植入任意工作空间。包内含 manifest（id、标题、语言、`StartedAt` /
    `EndedAt`）、`transcript.md`、`transcript.jsonl`、`attachments/`；导出时一个勾选框决定是否含
    `audio.wav`，**默认不含**（一小时约 115 MB，邮件发不动）。
23. 导入按记录 id 判重，提供**跳过／另存为新记录**两个选项，**不提供覆盖**。双向同步是另一个量级
    的问题；提供「覆盖」按钮等于承诺一套我们没有实现的合并语义，一次误点抹掉一小时录音。

### H. 知情确认

24. 知情确认从工具栏上的常驻复选框移入**点录制时弹出的对话框**，按
    [`meeting-ui.prototype.html`](../design/meeting-ui.prototype.html) 的 `consent()` 实现：两个独立
    勾选项（同时保存音频文件／我已告知所有参与者），后者未勾时「确认并开始」禁用。
25. 弹窗里的「同时保存音频文件」是**本场一次性覆盖**，不写回设置——为某一场敏感会议临时取消勾选，
    不应让下一场默默不录音。
26. Esc 与点击窗外都算取消，取消后原地不动。`consent-confirmed-at` 记录「确认并开始」被按下那一
    刻——它会进入 Markdown 导出，是合规凭证。
27. 远程参与者提醒作为固定小字常驻，线上采集档案下再额外强调。当前实现按采集档案在室内／线上两套
    文案间二选一，会让混合会议（室内几人 + 线上几人）完全看不到远程提醒，而采集档案只有一个值。

### I. 删除

28. 会议的三点菜单增加删除：二次确认、写明转写与录音将一并删除且无法恢复、**永久删除不经回收站**、
    活动会议禁用该项。存储层的 `DeleteMeeting` 已经存在，只需接上 UI。

## 实施切片

每片一个 PR，各自留下全绿的测试套件。

### 1. 存储契约：转写落进记录

接线 `StartedAt` / `EndedAt`；`meetings/<id>/` 下的 `transcript.jsonl` 边开边追加；录音改写入记录
文件夹；`RoomId` 退出文件命名；删除设置里的 `AudioFolder`。（决定 5–8）

### 2. 生命周期与标题

知情确认弹窗；确认后才创建记录；空白记录复用规则；首启自动创建默认工作空间；默认标题与唯一性
校验。（决定 1–4、9–11、24–27）

### 3. 活动会议与所浏览记录

中栏切换到被选记录的只读视图；写操作锁定活动会议（顺带修掉标题写错记录的缺陷）；左栏高亮与返回
横幅。（决定 12–14）

### 4. 导入导出

取消 JSON 导出；单场会议迁移包与其 manifest；导入判重。（决定 20–23）

### 5. 右栏文件页签

文件树的显示与导入。（决定 18–19）

### 6. 导航刻度尺（结构层）

按发言人切换实时铺底，悬停预览，点击跳转。（决定 15–16 的前半）

### 7. 导航刻度尺（语义层）

**依赖 [#34](https://github.com/TONiiV/Kanal/issues/34)。** 议题边界叠加为亮刻度，与右栏「要点与
决策」双向联动。（决定 16 的后半、17）

### 8. 删除会议

三点菜单、二次确认、活动会议禁用。（决定 28）

## 验证

- 转写在会议进行中就出现在记录文件夹里，主机被强杀后已写入的部分仍可读。
- 录制中浏览另一条记录：中栏换成那条记录，生成的标题写进**活动**会议而非被浏览的那条，返回横幅
  出现，点击可回到活动会议。
- 取消知情确认后，工作空间里不多出任何记录。
- 手工把两场会议改成同名会被拒绝；模型生成撞名时自动加后缀且不打断会议。
- 迁移包在另一台机器上导入后重建出同一条记录；第二次导入同一个包只给出跳过／另存两个选项。
- 删除后转写与录音都不在磁盘上。

## 后果

- 记录文件夹成为转写和录音的**唯一**一份。删除一条记录从「清掉一个空壳」变成「销毁一小时不可再现
  的证据」，这也是第 28 条要求二次确认并写明后果的原因。
- 记录数量会显著增加：今天工作空间是空的，之后每场会议都留下一条。
- 允许在录制中浏览历史记录，意味着「活动会议」与「所浏览记录」两个状态必须一直并存，每一处写操作
  都要显式声明自己跟随哪一个。
- 刻度尺分两次交付：语义层要等 #34。

## 明确排除

- **一条记录装多次会话。** 由决定 1 排除；`RoomId` 每次 Start 必换、utterance id 归零，塞进一条记录
  只会把 id 冲突带进文件系统。
- **故事线面板。** 曾作为右栏的第四个页签讨论过：它与「要点与决策」讲的是同一件事，而它真正有用的
  那一面——会议脉络的关键节点——已由导航刻度尺的语义层承担。
- **让模型读取附件。** 仓库的架构不变量是只有文本穿越公网；把操作员拖进来的任意文件（合同、图纸、
  报价单）喂给云端 provider 是一个独立的安全决定，不能夹带在文件树里通过。
- **删除工作空间。** 工作空间维持「遗忘」语义（只删注册表条目，文件留在磁盘），本文不动它。
- **导入时覆盖已存在的记录。** 见决定 23。
