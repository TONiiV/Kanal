# 1.0.0 带更新检查与最低支持版本，完整 OTA 推迟

状态：accepted，2026-09-23。

没有更新检查的版本收不到任何更新通知；桌面安装包也无法远程撤回，relay 协议一变旧主机会静默出错。因此
`v1.0.0` 必须带上**更新检查**，并由**最低支持版本**把过旧的主机挡在开会之外。首发只做检查和提示，
不在应用内下载或安装：装机量只有少数操作员与测试者，而静默更新（Velopack / Sparkle）要替换现有 WiX MSI
与 dmg 公证链，MSI 未签名还会触发 SmartScreen，这些成本不该压在首发上。

## 决定

- **范围**：只针对桌面主机。模型下载、手机字幕页与 relay 各自部署或下载，不在内。只有一个发布渠道。
- **清单**：由 relay Worker 的 `?action=update` 返回，数值写在 `gateway/wrangler.toml` 的 `[vars]`，
  改动经 git 审阅、`wrangler deploy` 生效。主机把清单地址编译为常量，`KANAL_UPDATE_URL` 仅供测试覆盖
  （未配置 relay 的主机不知道 `KANAL_RELAY_URL`）。清单含最新版本、最低支持版本、更新日志摘要和可空的
  下载链接。
- **不带下载链接**：测试版经私密、可撤销链接分发，而清单接口公开；提示只显示版本、更新日志摘要和
  「联系维护者」。决定公开分发时填上下载链接即可，格式不变。
- **两端执行最低支持版本**：主机读清单后禁用 Start，禁用原因沿用现有「不可用原因」行内说明；relay 在
  `?action=create` 读取主机的 `X-Kanal-Version` 请求头并拒绝过低版本，缺失该头按 1.0.0 之前处理。
  客户端负责友好提示，relay 负责真正拒绝；两端共用 `[vars]` 里同一个数值。
- **拉不到清单就放行**：离线、被墙、404 或超时都照常使用、不提示。本地功能必须离线可用；强制执行靠 relay。
- **不打断会议**：启动时和之后每 24 小时检查一次，会议进行中不检查；进行中的会议即使低于最低版本也跑完，
  只禁止下一场。
- **不提供关闭开关**：能关就绕过了最低支持版本；完全断网的环境已经等价于关闭。请求只带版本号与平台，
  README 与知情说明写明这一次出网。
- **位置**：「新版本 x.y.z」提示位于左栏底部、与设置按钮同一行右对齐，不弹窗；设置「常规 → 版本」区块
  同时显示并提供「检查更新」。日后反馈按钮紧贴设置右侧（ADR 0052），更新提示仍在该行右端。

## 考虑过的方案

- **静默自动更新**：推迟，不是否决。装机量上来或发版频率让手动安装变得烦人时另开 ADR，与 MSI 签名一起做。
- **只靠客户端执行最低版本**：拉不到清单时放行，客户端检查可被绕过；relay 是唯一能真正拒绝旧主机的地方。
- **拉不到清单就拦截**：会让断网或大陆网络下的本地会议无法开始，违背本地功能离线可用。
- **清单放 GitHub Pages**：github.io 在大陆不稳定，且 relay 兜底还得另存一份最低版本。E 轨迁到 EdgeOne 时
  再评估是否迁移清单。
- **1.0.0 先发、1.0.1 再加检查**：1.0.0 的用户将永远收不到提示，只能逐个人工通知。

## 落地

- 本 PR：本 ADR、`CONTEXT.md` 术语、PRD v0.4 阶段 1、PROGRESS。
- 主机端：清单解析、版本比较与上述策略在 Core，TDD；左栏提示、设置区块、Start 禁用原因、四语 i18n、
  CHANGELOG；创建 room 时带 `X-Kanal-Version`。**必须在 `v1.0.0` tag（#125）之前合并。**
- Worker 端：`?action=update` 与 `create` 的最低版本校验。服务端部署，可在 1.0.0 之后合并，但应在主机第一次
  真实调用之前部署；在那之前主机拿到 404，按放行处理。
