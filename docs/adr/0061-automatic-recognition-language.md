# ADR 0061：转写语言全部自动识别，房间语言不限制识别

状态：accepted，2026-10-18。

会议里常有中英混说，有时还有中德、中波混说，会前无法知道谁会说哪种语言。我们决定：转写永远不限制识别的语言范围。
房间语言只决定屏幕上的语言列和翻译目标，不传给转写作为候选语言或强制语言。

## 决定

- **操作员不设定识别语言。** 设置里没有"识别语言"选项，房间语言也不当作识别语言用。
- **云端转写不发候选语言。** Gladia 只开 `code_switching`，不发 `languages`。`GladiaAsrProvider` 现在就是这样。
- **本地转写用自动模式。** 需要语言参数的模型（Nemotron 的提示词、离线模型的语言参数）一律传 `auto`。
  句子的语言由 `TranscriptLanguage` 从文字读出。
- **系统自己判断出的语言可以用。** 例如按发言人从前几句话判断主语言，再交给第二遍转写模型。
  这是自动识别的结果，不是人为设定的范围。
- **模型选型看自动语言的成绩。** 基准测试里的"指定语言"房间只用于诊断，不作为选型依据。

## 后果

- 识别可能给出房间里没有的语言。例如在 AMI 测试中，Gladia 把 25 段里的 6 段识别成威尔士语。
  这个错误我们接受，不用限制语言范围来消除。
- 只能在指定语言下工作的模型（Cohere Transcribe），只能用在第二遍转写，并且语言要来自系统自己的判断。
- Qwen3-ASR 1.7B 在自动语言下的成绩还没有有效数据：上一轮测试的文字里混入了模型的语言标记。选用前要重测。
- 现在的 `NemotronAsrProvider` 在房间只有一种语言时强制使用这种语言。这和本决定冲突，需要另开票修改。

## 考虑过的方案

- **把房间语言加上英文作为候选语言发给 Gladia：** 能消除威尔士语这类错误。但说其他语言的人会被强行识别成候选语言之一，
  而且以前限制成屏幕上的语言列时，英文句子被标成了其中一种语言。
- **由操作员在会前设定识别语言：** 混说的会议做不到，设错了整场的转写都会出错。
