# 会议工作空间：已确认 UI 设计

状态：用户于 2026-09-07 确认样品设计完成。本文定义后续实现目标，不代表桌面程序已经实现。

## 设计基线

采用最终 B 方案。原型随文档保存在 [meeting-ui.prototype.html](meeting-ui.prototype.html)，
可直接用浏览器打开，无需 CMD 启动器或预览服务。
原型用于理解布局和交互，正式 Avalonia 实现应重新组织组件，不能复制其多轮 CSS/脚本覆盖。

此前的本地归档提交 `4c4d3db` 保留为历史；当前以文档目录中的原型为查看入口。
原型中的模型、生成结果、公开会议、导出和持久化均为演示；
文本导入和音频试听只使用浏览器内存。历次验证仅覆盖脚本语法与 HTTP 可达性，
浏览器工具不可用，完整视觉及交互验收仍需在正式实现阶段完成。

## 三栏布局

| 区域 | 已确认内容 |
|---|---|
| 左栏 | 从顶部到底部；品牌与收起按钮、搜索与新建会议、项目选择器与添加菜单、会议记录、底部设置 |
| 中栏 | 顶部操作栏、会议标题及右侧语言旗标、转写正文；不显示额外项目名称顶栏 |
| 右栏 | 从顶部到底部；会议助手标题与收起按钮，要点与决策、发言人管理页签；未来增加 Agent 页签 |

两侧内边缘可拖动调宽，收起后正文应占用释放的空间，重新展开恢复宽度。
收起时，中间工具栏对应一侧提供展开按钮。三块区域必须有明确布局位置，不能因隐藏
子元素而将正文放入零宽列。左右顶栏与中部工具栏的分隔线保持同高。
原型使用 76px 顶栏、180–480px 侧栏范围和 320px 正文保留宽度作为参考尺寸，
这些是实现校准起点，不是跨平台像素验收标准。

## 中部操作与正文

- 左侧：处理模式选择；其右侧为会议收音模式（现场／在线）入口。
- 中央：录制控制，麦克风设备设置紧邻控制；右侧为加入会议二维码。
- 设置位于左栏底部；导入／导出不占用中部操作栏。
- 不出现横向滚动条或换行工具栏。收窄时中央控制优先可见，两侧从各自最左边开始保留，
  其余内容裁切；侧栏展开按钮也必须可访问。具体阈值需在 Avalonia 中校验。
- 操作使用一致的 SVG 图形；短说明放在 tooltip，复杂选择放入点击展开的面板。
- 正文显示会议标题；右侧是重叠圆形语言旗标，点击选择最多四种目标显示语言。
  删除“目标显示语言”文字及独立一行，删除正文“转写／摘要／决策”页签与多余小标题。
- 不再有两行横贯应用的状态／提示栏。简短运行状态放在录制控件附近。
- 发言人标签、原文、译文仍需清楚区分；语言选择、勾选框及图标按钮应对齐。

## 会议生命周期与知情确认

保留现有程序的开始、暂停／继续、停止语义。空闲显示红色录制圆点；运行中显示黄色暂停、
红色停止；暂停时可继续；模型加载中可以停止取消；结束期间避免重复操作。
UI 重排不能改变暂停时不向转写或 WAV 写入音频的约束。

每次开始真实会议前，操作者须确认已告知所有参与者并取得同意。远程会议明确提醒口头或
聊天告知；保存 WAV 是独立选择。保留开始前弹窗与会中紧凑状态说明，参会端亦需显示状态。
此设计调整了 ADR 0050 的主机提示位置，没有删除其知情确认要求；不宣称单靠此 UI 即满足 GDPR。

## 项目、会议与导入

工作空间为平级项目范围，每个对应用户选择的本地文件夹，包含多场会议的转写和摘要。
公司、团队、项目、个人用途均可作为工作空间名称，不引入公司／项目层级。

- 品牌下方搜索框筛选会议；同一行右侧独立按钮新建空白会议。
- 项目选择器旁的添加菜单包含“新建项目”和“导入新会议记录”。
- 导入接受录音与文本；录音进入待转写流程，文本成为会议记录。具体格式、重复处理、
  音频保留策略与失败恢复在实现导入功能时另定，原型的扩展名列表不等于正式支持承诺。
- 每场会议的三点菜单提供导入／导出；箭头向下为导入、向上为导出。
- 原型允许本地文本显示及录音试听，刷新后清除；正式持久化布局尚未实现。

## 右栏与设置

右栏“要点与决策”包含实时要点、议题→方案→决定及原文定位。模型提出的决定标为待确认，
由用户确认。发言人管理提供重命名及合并入口，保留现有非破坏合并语义。

设置窗口采用左侧纵向页签，覆盖通用、音频输入、本地转写、翻译、智能总结和工作空间。
保留当前版本、开源许可等现有设置的入口。首选本地 ASR 为 Nemotron 3.5 ASR Streaming 0.6B；
参考 Handy 的模型管理体验与兼容范围，但须逐项验证，不能声称已经具备全部模型支持。
优先验证 Windows NVIDIA，同时调查 CPU 与 Apple Silicon 路径。

## 新增功能与交付顺序

用户已要求会议标题默认由本地模型生成，支持手工重命名与重新生成。
未来 Agent 页签连接本地 harness CLI 或带 API key 的模型 provider，持续旁听并支持
提问、主动信息建议及事实核查。这两项的已确认目标和未定边界见
[标题与旁听 Agent 讨论](meeting-intelligence.md)。

另外已要求发言人识别及点击句子回放原录音片段，工作项与未定范围见
[会议证据能力](meeting-evidence.md)。这些是后续功能，不视为原型已经提供。

交付按此前确认的顺序推进：

1. Avalonia 布局、图标、侧栏与设置重排；保留现有录制语义和知情确认。
2. 本地转写及模型管理，验证实际硬件、语言和流式行为。
3. 持久化工作空间、导入、标题、总结与决策功能，分别明确数据契约。
4. 旁听 Agent，待访问范围、生命周期与主动行为边界明确后实施。

## 正式实现验收

- 四种侧栏开合组合及拖动宽度均不挤毁正文，顶部分隔线一致，设置可访问。
- 窄窗口、长名称、多语言标签下中央控制保持可操作，没有横向工具栏滚动。
- 开始、加载取消、暂停、继续、结束、失败与重试符合现有行为。
- 每次真实开始都重新确认知情；暂停不继续送音频；保存音频的状态表达准确。
- 会议搜索、新建、菜单、语言选择及设置页签键盘可达；图标具有可访问名称。
- 真实文件导入不会误覆盖其他会议；工作空间切换不混淆活动会议与所浏览记录。
- Avalonia 行为变更遵循仓库测试规则；原型语法检查不能替代实现测试或视觉验收。
