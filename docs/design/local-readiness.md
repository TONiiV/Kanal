# 本地运行检查与 Gladia 设置引导

状态：2026-09-07 新增需求，grill-with-docs 讨论中，尚未实现或追加到已发布规格。

## 已确认目标

- 自动分析本机是否满足本地转写、本地翻译的最低配置要求。
- 不满足时推荐 Gladia API，并展示配置教程。
- 这一检查服务于已确认的本地模型选择流程，Nemotron 3.5 仍是本地 ASR 首选。

## 现有实现事实

PipelinePlanner 目前检查 Gladia key 是否配置、翻译模型选择与下载状态。
本地 ASR 仍被标记为未实现；这不是用户机器不达标。
云翻译仅通过云 ASR 会话提供，尚无独立的本地 ASR → 云翻译 provider。
本地模型已有 warm-up 入口，但能加载不代表能同时满足实时转写与多语言翻译的性能需求。

## 待确认方案

1. **判定标准**：建议分为轻量静态检查与可取消的短基准测试。检查所选模型和后端支持、
   内存／显存／磁盘、运行环境，再验证加载和实际处理速度。转写、翻译及组合分别给出结果。
   模型、量化、后端和语言列数都会影响要求，不预设未经验证的统一 RAM／GPU 门槛。
2. **结果含义**：建议区分可用、性能可能不足、硬性不兼容、尚未验证，以及未下载／未实现。
   检测不到 GPU 不应自动等于“不满足”；CPU 或 Apple Silicon 路径以所选后端实际能力为准。
3. **降级行为**：建议只推荐并引导，由用户明确选择后切换；不能仅因自动检测而发送会议音频。
   可以运行但较慢时允许继续本地，硬性不兼容时说明阻塞原因并禁用对应本地组合。
4. **组合推荐**：建议在本地翻译可用而本地 ASR 不可用时推荐 Gladia 转写＋本地翻译；
   翻译也不可用时推荐 Gladia 转写＋翻译。不得推荐当前尚未实现的本地 ASR＋独立云翻译。
5. **教程**：建议在设置中展示注册／登录、获取 API key、填入设置、测试连接、选择模式、
   开始前告知参与者的流程。说明实际数据去向与可能费用，链接官方资料；不硬编码额度和价格。
   key 不进入日志或诊断导出。测试网络连接与上传测试音频是不同操作，需要清楚说明。

以上均为建议，尚未由用户确认。后续还需明确测试触发时机、缓存与重新检测、性能验收指标、
无网络时的引导方式、教程本地化、检测失败处理及模型不满足时是否优先尝试更小本地模型。

## 测试入口建议

沿用主机视图模型／PipelinePlanner 公开状态，用可注入的设备与基准结果验证推荐和可用性。
缺 key、未下载、未实现、加载失败与硬件不兼容必须显示不同原因；不在 CI 探测真实 GPU 或下载模型。
真实硬件验证单独记录，确保评估转写与翻译同时运行而不是仅各自运行。

## 官方教程依据（2026-09-07 核对）

- [注册与 API key](https://docs.gladia.io/api-reference/authentication)：控制台获取 key，API 使用 `x-gladia-key`。
- [Getting started](https://docs.gladia.io/chapters/introduction/getting-started)：教程总入口。
- [实时转写 quickstart](https://docs.gladia.io/chapters/live-stt/quickstart)：创建 live session 后通过 WebSocket 发送音频。
- [Live session 配置](https://docs.gladia.io/api-reference/v2/live/init)：实时翻译作为转写会话配置。

额外实现注意：当前 LLamaSharp 项目引用 CPU backend；设置 GPU offload 参数或检测到显卡，
不代表已分发后端能够利用该 GPU。就绪检查必须包含实际加载的后端能力。
