# Kanal PRD v0.4 — 首发收尾与六轨路线图

> 接替 [v0.3](PRD-v0.3.md)（2026-07-29）。v0.3 的 M0 已交付，本版把范围和计划对齐到仓库的实际状态，
> 并给出首发版本 1.0.0 的截止线。架构与界面约束沿用 v0.3，只记录变了的部分。

**主机**：.NET 10 + Avalonia · Win / macOS，双击安装（dmg 公证 / MSI），自带运行时
**手机端**：静态页 · 纯只读 · 无外部字体与 CSS
**公网上跑什么**：只有文本，经鉴权的 Cloudflare Worker 网关
**首个目标**：发布 1.0.0，一场真实的 zh/de/pl 会议里不再做人力双重翻译

## 00 — 定位不变：内部工具，不是产品

评判标准仍然只有一条：**省下的时间是否多于花掉的时间。**

真实场景、无共同语言兜底、竞争对象是一个已经崩溃的流程——见 v0.3 §00，一字未改。

### 相对 v0.3 的变更

| v0.3 | 状态 | v0.4 |
|---|---|---|
| 托管 pub/sub（Ably / Supabase） | 替换 | **自有 Cloudflare Worker 网关**：房间对象、激活码、快照回放、过期关闭码。零长期维护的服务端代码这一条没守住，但换来了鉴权与大陆自定义域名的余地 |
| 本地模型经 Python 子进程 | 替换 | **进程内**。翻译已是 ONNX 进程内运行（Qwen3）；转写走 sherpa-onnx（ADR 0053），不起子进程 |
| Gladia `Diarization ✓` | 纠正 | Gladia 实时流**不分离发言人**。所有句子落到 `S01`。分离是自建的分层方案（ADR 0055） |
| 流式 Sortformer 分离 | 放弃 | 实时层改为逐句嵌入 + 在线聚类，会后对完整录音重跑权威分离（ADR 0055） |
| MOSS 会后纪要重跑 | 放弃 | 会后重跑只做发言人分离；要点与决策由监听模型给出（[meeting-intelligence](design/meeting-intelligence.md)，未定） |
| 远程参会者走 Recall.ai 类 bot | 替换 | **原生系统音频采集**（WASAPI loopback / Core Audio process tap），麦克风与电脑声音混成一路（ADR 0050） |
| 「M1 / M2 按需」 | 替换 | 六条 ADR 轨，每轨切成 PR 大小的片，见 §06 |
| 单一会议、导出即结束 | 扩展 | **工作空间拥有会议记录**：转写边开边写进记录，可浏览、导入、删除（ADR 0051、0054） |
| md/json 纪要导出 | 收窄 | JSON 导出取消，改为单场会议迁移包；Markdown 保留（ADR 0054 决定 20–23） |
| 无账号 | 推迟 | 账号只用来控制云服务访问，反馈不要求账号（ADR 0052）。1.0.0 之外 |

## 01 — 架构：音频全在本地，公网只跑文本

主机是唯一权威，手机是投影，晚入房与重连由 `room.snapshot` 服务——v0.3 §01、§03 全部成立。

改了的只有中继一层：`IRelayPublisher` 后面现在是自有网关，不是第三方 pub/sub。`workers.dev` 默认域名在大陆
被墙（[#41](https://github.com/TONiiV/Kanal/issues/41)），中国供应商的手机走国内运营商时需要自定义域名。
这是 E 轨的验收条件，不是 1.0.0 的。

**「音频不出本机」仍然不成立。** 云转写模式把房间音频发给 Gladia，主机顶栏与手机页都有实时转写声明，
Start 被全员知情确认挡住，确认时间写进导出头。严格成立要等 C 轨的本地转写落地。

## 02 — Provider：能力声明式，不按厂商分支

接口与编排规则同 v0.3 §02。实现表按现状更正：

| 实现类 | Caps | 状态 |
|---|---|---|
| `GladiaAsrProvider` | Streaming ✓ **Diarization ✗** Translation ✓ AutoLang ✓ Realtime | 1.0.0 默认 |
| `LocalMtProvider`（Qwen3，ONNX 进程内） | — | 已交付，含模型目录与下载 |
| `NemotronAsrProvider`（sherpa-onnx） | Streaming ✓ Diarization ✗ Translation ✗ Realtime | C 轨，未建 |
| `ISpeakerAttributionService` | 实时暂定 + 会后权威 | B 轨，未建；`if (!asr.Caps.Diarization)` 路由 |
| 独立云翻译 | — | 不存在。Local→Cloud 模式不可用 |

## 03 — 事件与状态

同 v0.3 §03。`Utterance` / `Speaker` 记录、五种频道消息、非破坏合并、`Speaker.MergedFrom` 解析——全部不变。

## 05 — 范围

### 1.0.0 之内

已在 `main` 上的：Avalonia 主机与安装包、麦克风采集与设备热插拔、Gladia 云转写、Qwen3 本地翻译、
五种管线模式（不可用的自述原因）、主机四列与识别语言标注、二维码与手机只读页、快照回放与重连、
激活码与频率限制、三栏工作空间壳、会议标题与自动命名、六页设置、日志隐私分级、知情确认门禁与导出证明。

随收尾 sprint 并入的：转写边开边写进会议记录、记录的生命周期与默认标题、活动会议与所浏览记录分离、
单场会议迁移包、右栏文件页签、转写导航刻度尺（结构层）、删除会议记录、会议时间轴与音频索引、
工具栏悬停与禁用墨色修复。

### 1.0.0 隐藏或禁用

不能用的功能不上屏，而不是上屏后说不能用。**规则：一个控件如果在 1.0.0 里没有第二种状态，就不出现。**

| 功能 | 处置 | 原因 |
|---|---|---|
| 右栏「发言人」页签 | 隐藏 | 实时流只有 `S01`，没有第二个人可以改名或合并。B 轨片 4 接上后恢复 |
| 采集画像「在线会议」 | 禁用，行内说明 | 系统音频适配器在 D 轨，选了也只录麦克风 |
| Local→Cloud、Local→Local 模式 | 已是禁用态 | 沿用现有「不可用原因」机制 |
| JSON 导出 | 删除 | A 轨片 4 |
| 设置里的 `AudioFolder` | 删除 | 录音随记录走（A 轨片 1） |

### 1.0.0 之外

本地转写、发言人分离、系统音频采集、要点与决策的监听模型、账号与云配额、免账号反馈、录音导入、
手机页迁出 GitHub Pages、大陆整链路验收、声纹、E2E 加密、TTS、Teams 侧板。

## 06 — 路线图

六条轨各由一份 ADR 定义，每轨切成 PR 大小的片，每片一个 PR、TDD、套件全绿。阶段之间**串行**：
一个阶段的验收没过，不开下一个阶段的片。阶段内可以并行。

### 阶段 0 · 已交付（`main` @ 1.0.0 前）

v0.3 的 M0 全部，加工作空间壳、安装包链、网关加固。**M0 的验收「停止人力翻译」还没有在一场真实会议
上跑过**——它是 1.0.0 发布后第一场会议要回答的问题，不是已经回答了的。

## 07 — 风险

| 风险 | 严重度 | 现状 |
|---|---|---|
| 中↔波技术术语翻不对 | 最高·未在真实会议验证 | 本地翻译基准里料号与标准保留（PROGRESS 2026-08），但真实会议材料上的中↔波质量仍是 go/no-go 门槛 |
| 首发带着「一个发言人」 | 高·沟通 | 藏页签，README 说实话。阶段 4 之前不承诺分离 |
| 半成品切片合进 `main` | 高·流程 | 阶段串行；一片没合完不开下一片；合完立即删 worktree |
| 十六个 PR 挂四天 | 中·流程 | 本 sprint 清空。此后待合 PR 超过五个即停开新片 |
| 大陆连不上网关 | 中 | 阶段 5 的验收条件，自定义域名 |
| 本地转写在 8 GB GPU 上跑不动 | 中·未验证 | 阶段 3 C-4 第一件事是测速，慢于 1× 实时即换模型 |
| 系统音频权限在 macOS 上被静默拒绝 | 中 | `InstallerLayoutTests` 守用途字符串与 entitlement；阶段 2 在干净 Mac 上验 |
| 「音频不出本机」到阶段 3 才成立 | 低·沟通 | 顶栏与手机页已声明；同意门禁已挡 Start |

**停止条件**：v0.3 的那条不变——1.0.0 之后的第一场真实会议里仍在做人力翻译，**停掉项目，不要改进它**。
阶段内的：阶段 1 的 30 分钟模拟会里操作员仍需要碰键盘之外的东西，或阶段 2 的真实 Teams 会议里远端
一句话没进转写——停下来修，不开下一阶段。
