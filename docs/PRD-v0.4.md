# Kanal PRD v0.4 — 首发收尾与六轨路线图

> 接替 [v0.3](PRD-v0.3.md)（2026-07-29）。v0.3 的 M0 已交付，本版把范围和计划对齐到仓库的实际状态，
> 并给出首发版本 1.0.0 的截止线。架构与界面约束沿用 v0.3，只记录变了的部分。

**主机**：.NET 10 + Avalonia · Win / macOS，双击安装（dmg 公证 / MSI），自带运行时
**手机端**：静态页 · 纯只读 · 无外部字体与 CSS
**公网上跑什么**：只有文本，经鉴权的 Cloudflare Worker 网关
**首个目标**：发布 1.0.0，一场真实的 zh/de/pl 会议里不再做人力双重翻译

## 00 — 定位不变：内部工具，不是产品

评判标准仍然只有一条：**省下的时间是否多于花掉的时间。**

真实场景、无共同语言兜底、竞争对象是一个已经崩溃的流程——见 v0.3 §00，一字未改。

### 相对 v0.3 的变更

| v0.3 | 状态 | v0.4 |
|---|---|---|
| 托管 pub/sub（Ably / Supabase） | 替换 | **自有 Cloudflare Worker 网关**：房间对象、激活码、快照回放、过期关闭码。零长期维护的服务端代码这一条没守住，但换来了鉴权与大陆自定义域名的余地 |
| 本地模型经 Python 子进程 | 替换 | **进程内**。翻译已是 ONNX 进程内运行（Qwen3）；转写走 sherpa-onnx（ADR 0053），不起子进程 |
| Gladia `Diarization ✓` | 纠正 | Gladia 实时流**不分离发言人**。所有句子落到 `S01`。分离是自建的分层方案（ADR 0055） |
| 流式 Sortformer 分离 | 放弃 | 实时层改为逐句嵌入 + 在线聚类，会后对完整录音重跑权威分离（ADR 0055） |
| MOSS 会后纪要重跑 | 放弃 | 会后重跑只做发言人分离；要点与决策由监听模型给出（[meeting-intelligence](design/meeting-intelligence.md)，未定） |
| 远程参会者走 Recall.ai 类 bot | 替换 | **原生系统音频采集**（WASAPI loopback / Core Audio process tap），麦克风与电脑声音混成一路（ADR 0050） |
| 「M1 / M2 按需」 | 替换 | 六条 ADR 轨，每轨切成 PR 大小的片，见 §06 |
| 单一会议、导出即结束 | 扩展 | **工作空间拥有会议记录**：转写边开边写进记录，可浏览、导入、删除（ADR 0051、0054） |
| md/json 纪要导出 | 收窄 | 唯一导出是单场会议的 `.kl` 文件；会议导入只接受 `.kl`，其他文件成为附件。Markdown 转写只在 `.kl` 包内（`transcript.md`）（ADR 0054 决定 20–23，2026-10-07 修订） |
| 无账号 | 推迟 | 账号只用来控制云服务访问，反馈不要求账号（ADR 0052）。1.0.0 之外 |

## 01 — 架构：音频全在本地，公网只跑文本

主机是唯一权威，手机是投影，晚入房与重连由 `room.snapshot` 服务——v0.3 §01、§03 全部成立。

改了的只有中继一层：`IRelayPublisher` 后面现在是自有网关，不是第三方 pub/sub。`workers.dev` 默认域名在大陆
被墙（[#41](https://github.com/TONiiV/Kanal/issues/41)），中国供应商的手机走国内运营商时需要自定义域名。
这是 E 轨的验收条件，不是 1.0.0 的。

**「音频不出本机」仍然不成立。** 云转写模式把房间音频发给 Gladia，主机顶栏与手机页都有实时转写声明，
Start 被全员知情确认挡住，确认时间写进导出头。严格成立要等 C 轨的本地转写落地。

## 06 — 路线图

六条轨各由一份 ADR 定义，每轨切成 PR 大小的片，每片一个 PR、TDD、套件全绿。阶段之间**串行**：
一个阶段的验收没过，不开下一个阶段的片。阶段内可以并行。

> **2026-10-08 修订：先验证，后建设。** 一份外部评审指出：go/no-go 问题（中↔波术语）还没有答案，
> 项目已在中继、凭证、四种界面语言和会议智能上投入。仓库状态证实了这一点：1.0.0 未发布，
> 待合 PR 有 11 个，超过 §07 的 5 个上限，其中 4 个属于阶段 3、4。
> 本次修订在阶段 1 和阶段 2 之间加一道**验证闸门**（阶段 1.5）。闸门没过，阶段 2 及以后的片不开、
> 不评审、不合并。闸门的数据决定后续阶段的顺序：错误最大的一环先修。评审要点与取舍见
> PROGRESS 2026-10-08。

### 阶段 1.5 · 验证闸门（V 轨）

回答 v0.3 以来一直没回答的问题：**中↔波、中↔德的真实会议，数字和术语翻得对不对。**
这一阶段不加界面，只加一个可重复的测量。

| 片 | 内容 | 状态 |
|---|---|---|
| V-1 | 评测方案：录 2–3 场真实或模拟的 zh/de/pl 技术会议（知情同意）；人工校对原文与译文，存为参考稿 | 未开 |
| V-2 | `KeyFactExtractor`（`Kanal.Core`，纯函数）：从一句话里抽数字、单位、公差、料号、标准号、日期；按语言对比原文与译文 | 未开 |
| V-3 | `tools/` 下一个评测命令：读 `.kl` 与参考稿，按语言对输出关键事实错误率、术语错误率、final 延迟 | 未开 |
| V-4 | 拾音对比：同一场会，笔记本麦克风与 USB 会议麦各录一路，比较转写错误率 | 未开 |

V-2 是阶段 2 F 轨的同一个抽取器。评测与实时报警用一份代码。

**闸门**（阈值待确认）：

1. 每个语言对的关键事实错误率 ≤ 2 %，中↔波包括在内。
2. 一场真实会议里，旁观者判断不需要人力重新翻译。

**闸门的结果决定下一步**：

| 主要错误来源 | 下一个阶段 |
|---|---|
| 翻译把数字或术语改错 | F 轨（关键事实与术语） |
| 转写就听错了 | 拾音与 C 轨（本地转写的术语热词） |
| 都低于阈值 | 按原顺序继续 |
| 中↔波高于阈值，且 F 轨两片后仍高于阈值 | 停止条件，见 §07 |

**冻结**：阶段 3、4 的待合 PR（#126 #127 #146 #147）保持打开，不评审，不合并，直到闸门通过。

### 阶段 1.6 · F 轨：关键事实与术语（闸门通过后的默认首位）

通用翻译产品不做的一件事：**说出口的数字和料号，译文里必须一样。**原文 0.05 mm、译文 0.5 mm
是工业会议里最贵的错误。

| 片 | 内容 |
|---|---|
| F-1 | 实时比对：每个 final 跑 V-2，原文与译文的关键事实不一致时，主机该句标红并给出原文值。首版只在主机显示（会议智能 A4：猜测不广播给参会者） |
| F-2 | 术语表导入：从 BOM、规格书的 CSV/XLSX 导入 zh/de/pl 对照；进本地翻译的上下文，进 Gladia 的自定义词汇（待核实实时流是否支持） |
| F-3 | 术语表命中率进 V-3 的评测输出 |

**验收**：V-1 的参考会议重跑，关键事实错误率下降，或者每个剩下的错误都被 F-1 标出。

### 阶段 4.5 · G 轨：会议结论与当场确认（2026-10-08 新增，需新 ADR）

供应商会议里最贵的往往不是听不懂，而是事后对「当时说定了什么」有争议。
G 轨把 [meeting-intelligence](design/meeting-intelligence.md) 的开放讨论收窄成一个可验收的目标。

| 片 | 内容 |
|---|---|
| G-0 | ADR：手机端的回写通道。手机从纯只读变成「只读 + 两种上行消息」，主机仍是唯一权威。这改动 §04 冻结规则与「客户端是投影」不变量，必须先决定 |
| G-1 | 结构化纪要：决定、约定的数值与交期、负责人。每条带原句引用，数值经 V-2 校验 |
| G-2 | 每方用自己的语言看同一份纪要，在手机上逐条确认；确认人和时间写进 `.kl` |
| G-3 | 最小反馈：参会者点一句标记「没看懂，请重复」，或用母语发一个短问题，翻译后出现在主机屏幕 |

**验收**：一场真实会议结束时，三方各自在手机上确认了同一份纪要；会后没有人对纪要里的数值提出异议。
