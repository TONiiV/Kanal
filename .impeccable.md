# Impeccable — Kanal

Design context for `github.com/TONiiV/Kanal`. Gathered 2026-07-30. Read this before any design work.

## Design Context

### Users

**Operator (1 person).** The project owner, running the host laptop on the meeting table at a Poland
project meeting. Bilingual zh/de. Drives the whole session with a few controls: pick mode, pick
languages, Start, rename a speaker, Stop, export. Everything else must be readable at a glance from a
metre away while they are also participating in the conversation.

**Participants (3–8 people).** Chinese supplier staff, Polish contractor staff, German-speaking
parties. They scan a QR code and read a phone one-handed, mid-conversation, then look back up. The
page is read-only and there is exactly one control on it (language). They are not "using an app" —
they are glancing at a caption and returning to the room.

**The job to be done.** Replace a human zh→de→pl double-translation chain. The tool is judged solely
on whether it saves more time than it costs. Content is technical and unforgiving: part numbers
(`KX-4402`), surface-treatment standards, tolerances, drawing releases, delivery dates. Misreading one
character of a part number is more expensive than reading three fewer lines.

Nobody is a designer. Nobody will be trained. Nobody will hover to find a tooltip.

### Brand Personality

**Precise. Calm. Unbranded.**

Kanal is an instrument, not a product — it should feel like a well-made piece of equipment that was
already in the room. No logo worship, no onboarding, no personality performance, no delight for
delight's sake. A joke in a translation bubble is a bug.

Voice is terse and factual. Status text is trilingual where it actually matters (`连接中… / Łączenie… /
Verbinde…`) and absent otherwise. The emotional goal is one thing only: confidence that what is on
screen is exactly what was said.

### Aesthetic Direction

**Swiss editorial typography.** Strict grid, strong type-size hierarchy, generous white space, a
single accent. Character comes from typesetting and rhythm — not from texture, gradients, or effects.
Language columns behave like newspaper columns and bilingual signage. Left-aligned, ragged right,
never centred.

**Theme.** Mobile follows `prefers-color-scheme` (participants' phones are in unpredictable light).
Desktop host stays light — but on *explicit* brushes, never inherited FluentTheme defaults, because
following the OS dark theme previously made control foregrounds invisible.

**Palette.** Keep the existing cool-neutral ink family and the three earthy speaker accents
(rust `#B23A2E` / ochre `#9A6B10` / pine `#1C6B58`). These are load-bearing, not decorative: speaker
colour is the one signal that must survive a rename and a merge, and it is already shared between host
and mobile client.

**Anti-references.** SaaS dashboard card grids. Glassmorphism. Purple→blue gradients, cyan-on-dark,
neon accents. Chat-app bubbles with fat rounded corners and drop shadows. Monospace used as shorthand
for "technical". Large rounded icons above every heading. Centred hero layouts.

### Design Principles

1. **The live utterance is the design.** The newest, still-partial line carries the most visual weight;
   finalised history recedes in *contrast*, never in legibility. Everything else on screen is chrome and
   must behave like chrome.

2. **Typography is the only ornament.** Hierarchy comes from size, weight, and measure. No cards inside
   cards, no shadows faking depth, no rules that aren't structural.

3. **Speaker identity is colour, and colour is load-bearing.** Rust / ochre / pine identify a *person*
   across rename and merge. Never spend those hues on anything else, and never rely on colour alone —
   the tag or name is always rendered too.

4. **Set for three scripts at once.** Latin, Polish diacritics, and CJK share every surface. Font stack,
   line-height, and measure are chosen for the worst case — a Chinese sentence stacked against
   "wsporników" — not for English.

5. **Nothing the PRD froze may move.** Host ≤ 4 language columns; mobile single column + language
   dropdown; translation on top, source below; partial = muted, final = full ink; no TTS. This is a
   visual redesign inside a fixed information architecture.

## Technical Constraints

- **Two rendering stacks, one design language.** The host is Avalonia 11 XAML (no CSS, no `clamp()`, no
  container queries, no media queries — fluid type must be faked with fixed steps). The mobile client is
  a single self-contained static HTML file with **no build step and no external CSS/JS at load time**;
  the Supabase SDK is the only runtime import.
- **`web/index.html` and `docs/index.html` must stay byte-identical** — `docs/` is the GitHub Pages copy.
- Mobile must survive a lock-screen reconnect from `localStorage` cache, so styling can't depend on a
  full snapshot having arrived.
- Target for the host window: 1280×760 and up, 1–4 columns, `UniformGrid Rows="1"`.
